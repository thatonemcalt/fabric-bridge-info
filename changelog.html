Current release

FabricBridge 1.0

20 Nov 2026· Minecraft 1.21.11· Paper / Purpur· Java 21+

The build that is on Modrinth right now. Everything below is in this jar — no separate hotfix to install.

Fixes in this build

  • Clients without the mod stay connected. Custom mod chat colours now go over the wire as hex, so a player whose client lacks the mod no longer disconnects a second after joining.
  • Players on other Minecraft versions finish joining. Vanilla registry data is no longer re-synced to clients arriving through ViaVersion / ViaBackwards, which used to fail with "received registry entries that are unknown to this client".
  • Mods that extend vanilla classes keep working. Constructors that drifted from the server's runtime are filled in at load time instead of throwing at a player join — the FTB Library colour class is the known case.
  • /fb status reports initializers correctly. It used to print initializers run: false for a whole session, even after every entry point had run.
  • Client-only mods are accounted for. A mod with "environment": "client" is named once at boot, listed by /fb mods, and explained by /fb why <mod> — instead of silently missing from the boot count.
  • Boot scans the mod folder once. Datapack discovery reuses the resolved mod list, so nested jars are not extracted a second time.
  • /fb help always shows the real version. It reads the jar's manifest, so it no longer falls back to 0.10.x when the core failed to start.
  • Third-party notices ship in the jar. THIRD-PARTY-NOTICES.txt carries the ASM (BSD-3-Clause), Gson (Apache-2.0), Mixin and MixinExtras (MIT) texts.
Verified before upload: this exact jar was booted on Purpur 1.21.11 build 2568 and on stock Paper 1.21.11 build 132 — 41 mods, clean boot and shutdown, 0 crash reports. The same 1.0 runtime also passed protocol joins from 1.21.11, 26.2-claiming and 1.21.9-claiming clients.

Which versions still get fixes

Each release targets one Minecraft version. Only supported versions receive new fixes.
